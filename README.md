# DN1Sup Benchmark (dn1sup_benchmark)

Бенчмарк производительности SketchUp: чистый Ruby, операции SketchUp Ruby API,
файловые операции, FPS вьюпорта. Раздельно оценивает разные подсистемы и
предназначен для сравнения версий SketchUp на одной машине. Набор тестов v3
(схема отчёта v1, см. `dn1sup_benchmark/schemas/result-schema-v1.json`).

## Что измеряет

| Категория | Тесты (id) |
|---|---|
| Чистый Ruby | `RUBY-01` — фиксированная нагрузка: массивы, хеши, арифметика (без API) |
| SketchUp API | `API-01` рёбра+грани, `API-02` группы, `API-03` определения+экземпляры (с указанием, переиспользуются ли определения), `API-05` атрибуты (запись+обратное чтение), `API-06` операции модели: modify / commit / abort раздельно |
| SketchUp API (легаси) | `scene_gen_*` построение сцен, `hierarchy_*` навигация (`active_path=`), `pushpull_batch`, `texture_load_*`, `apply_texture_batch`, `repaint_textured`, `apply_color_batch` |
| Файлы | `DOC-01` сохранение контрольной модели, `DOC-02` открытие |
| Графика (вьюпорт) | `fps_grid_static/orbit/pan/zoom`, `fps_textured_static` — FPS рендера на сценах сетки/текстур, `zoom_extents` |

Тестовые сцены детерминированы (только формулы, без случайностей) — на любой
версии SketchUp геометрия идентична, метрики сравнимы.

## Методика

- Время — только монотонные часы (`Process.clock_gettime(CLOCK_MONOTONIC)`).
- Каждый тест: повторы (по профилю), в отчёте — все исходные длительности,
  median/min/max, p95 (при ≥10 повторах), ops/с (где определён объём работы).
  Медленные повторы не выбрасываются.
- Статус каждого теста: `passed` / `failed` / `cancelled` / `skipped`;
  ошибка теста не роняет прогон, диагностика (класс/сообщение/стек) — в отчёте.
- **Тяжёлая работа — кусочно**: построение сцен grid/textured и тесты
  API-01/03/06 выполняются порциями ~1 с (размер адаптируется); между
  порциями UI-поток свободен — SketchUp не «замерзает», отмена срабатывает
  максимум через ~1 с, панель показывает прогресс (N из M, фаза). Тайминг —
  только длительности порций, простои не считаются: методика замера от
  кусочности не меняется. Лёгкие тесты и единичные операции вида
  (`zoom_extents`) выполняются синхронно.
- Сцены строятся внутри undo-операции и откатываются (`clear! + abort_operation`):
  после прогона модель возвращается к исходному состоянию. Каждый `close_scene`
  сверяет число сущностей с базовым и пишет предупреждение в лог при расхождении.
- `API-06` выполняет вложенные операции уровня 1 внутри операции сцены
  (зафиксировано в параметрах теста); отдельной проверки отмены — путь abort.
- Прогон можно отменить (меню/панель): недозапущенный тест получает
  `cancelled`, отчёт всё равно сохраняется со статусом прогона `cancelled`.
- Прогон следит за активной моделью: если модель переключили — прогон
  аварийно останавливается БЕЗ очистки (очистка чужой модели недопустима).

### Переключение сцен (Pages) — только вручную

Автоматический FPS-тест переключения страниц (`Pages#selected_page=`) удалён:
применение страницы внутри открытой undo-операции фиксирует транзакцию ядра,
после чего `abort_operation` больше не откатывает контент модели
(инцидент 2026-10-28, SketchUp 2027 — геометрия открытой модели пострадала
в памяти; файл на диске не затрагивался). Переключение сцен измеряйте
ручным сценарием. Защитные меры в коде: page-switch не планируется в шагах,
`close_scene` не работает с чужой моделью, тесты сверяют откат сцен.

### Сцена компонентов — удалена (suite v3)

Сцена `components` (лес определений/сборок, до ~80 000 вложенных инстансов
на large) и FPS-тест `fps_components_static` удалены: на SketchUp 2027
вьюпорт зависает (100% CPU) на первом же простое после построения такой
сцены — не отрисовывается ни кадр (FPS замерить нельзя), блокируются все
последующие шаги прогона. Зависание воспроизведено тем же контентом на
свежей модели без бенчмарка; на масштабе medium (1024 сборки) проблем нет.
Тесты сцены (API-04 и легаси-дубли) в общий балл не входили; вклад API
компонентов остаётся в `API-03` (инстансы в сцене basics).

### Источники показателей

| Показатель | Источник |
|---|---|
| Длительности | внутренний замер (монотонные часы) |
| FPS | счётчик кадров Ruby-стороны: `Tool#draw` + `view.invalidate` — это НЕ GPU-счётчик |
| Версии SU/Ruby, платформа | `Sketchup.version`, `RUBY_VERSION` и пр. |
| CPU/ядра | `ENV[PROCESSOR_IDENTIFIER]`, `ENV[NUMBER_OF_PROCESSORS]` |
| DPI, размер вьюпорта, стиль рендера, тени | `UI.scale_factor`, `View#vpwidth/vpheight`, `RenderingOptions` |
| GPU-движок, загрузка CPU/GPU, VRAM | **нет источника** через SketchUp Ruby API — поля `null`, не 0 |

## Общий балл (необязательный, Geekbench-стиль)

Помимо раздельных оценок (основная часть отчёта) прон считается **необязательный
общий балл**:

- балл теста = `base/value` для мс (меньше — лучше) или `value/base` для fps
  относительно базового прогона;
- балл категории = геометрическое среднее баллов её тестов;
- общий балл = 1000 × взвешенное геометрическое среднее категорий.

**Веса категорий** (опубликованы, сумма = 1): API — 0.40, графика — 0.30,
чистый Ruby — 0.20, файлы — 0.10.

**База**: `baseline-small-v1.json` — фактический прогон small на
SU 2027.0.264 (2026-10-28). Это НЕ эталонное железо, а фиксированная шкала:
**1000 баллов = эта конфигурация**. Балл публикуется только для профилей с
baseline-файлом (пока `small`); для medium/large/custom — `unavailable` с
причиной. Пропущенные/упавшие тесты дают статус `partial` с перечнем
(ничего не подменяется нулями).

Тесты в балле (13): `RUBY-01`, `API-01/02/03/05/06`, `DOC-01/02` и пять
FPS-замеров. `API-04` исключён (субмиллисекундный — нестабильное отношение
к базе); `scene_gen_*` и легаси-дубли не участвуют, чтобы не считать одну
работу дважды; `fps_components_static` удалён вместе со сценой компонентов
(suite v3, см. выше).

Ограничения: балл сравним только между прогонами одного профиля и набора
тестов; FPS-часть зависит от частоты обновления дисплея (vsync-кап);
файловая часть чувствительна к кэшу ОС. Это сводная оценка для удобства,
**НЕ официальный рейтинг SketchUp** — первичны всегда раздельные результаты.

## Профили

| Профиль | Нагрузка (≈) | Параметры сцен |
|---|---|---|
| `small` | 10 000 рёбер; 100 инстансов | сетка 70×70, 100 инстансов (API-03), 3 повтора |
| `medium` | 16 000 рёбер; 300 инстансов | сетка 90×90, 300 инстансов (API-03), 2 повтора |
| `large` | 29 000 рёбер; 600 инстансов | сетка 120×120, 600 инстансов (API-03), 2 повтора |
| `custom` | задаётся пользователем | поля в панели; остальное — от small |

**Каждый полный прогон укладывается примерно в минуту** (решение владельца
2026-10-28; раньше large по целям ТЗ строил 500 тыс. рёбер и шёл десятки
минут — SU2027 деградирует на вставке в большие модели, см. CHANGELOG 0.4.0).
Число рёбер сетки ≈ 2·n·(n+1); цели по рёбрам/инстансам и формулы вывода
параметров записываются в отчёт (`meta.params`, параметры каждого теста).

## Запуск

- Меню **Extensions → DN1Sup → Benchmark**: «Панель бенчмарка…» (вкладки:
  Обзор, Тесты, Запуск, Результаты, Сравнение, Настройки) или пункты
  «Прогнать (small/medium/large)…». Перед каждым прогоном — подтверждение:
  бенчмарк временно создаёт и откатывает геометрию в текущей модели.
  UI не блокируется, отмена доступна в любой момент.
- Программно (мост/оркестратор): `Dn1supBenchmark.benchmark_steps(profile)` →
  пошагово `benchmark_perform(step)`; для FPS-шагов — пауза на время замера,
  затем `benchmark_fps_collect`; `benchmark_plan`, `benchmark_cancel`,
  `benchmark_last_run`, `benchmark_runs`, `benchmark_compare`.

## Отчёты и сравнение

Пишутся в `Documents/SketchUp Benchmarks/`: JSON (сырые данные, схема v1) и
самодостаточный HTML (таблицы + SVG-диаграммы, без интернета). Сравнение
(`Report.compare` / вкладка «Сравнение») считает проценты ТОЛЬКО для пар с
одинаковыми id, версией теста, единицами и параметрами нагрузки; несовместимые
пары помечаются с причиной (например, прогон 0.1.0 против 0.2.0 — разные
наборы тестов). DOC-тесты фиксируют размер файла и честно оговаривают тёплый
файловый кэш ОС — «холодный запуск» не заявляется.

## Совместимость

- **Проверено в живом SketchUp (фактические прогоны 2026-10-28, версия
  0.4.0)**: SU 2027.0.264 (Ruby 3.4.9) — 59/59 юнит-тестов и полные прогоны
  всех профилей без зависаний, каждый ≈ ≤1 мин: small ~25 с, medium ~30 с,
  large 60 с (26 записей на прогон, все passed; контроль — внешний сторож:
  маркерный файл перед каждым шагом + перезапуск при зависании).
  SU 2026.2.243 (Ruby 3.2.2) — установлены и зелёные тесты.
- **Наблюдения SU 2027**: `Sketchup.open_file`/`Model#close` дают warning
  «Deprecated overload, use with_status: true overload instead» (работают);
  вьюпорт зависает (100% CPU) на простое после сцены ~80 000 вложенных
  инстансов компонентов — по этой причине сцена components и
  `fps_components_static` удалены (см. CHANGELOG 0.4.0).
- **Проверено по API-вызовам в живом SU 2024.0.594** до его закрытия:
  `save_copy`, `Model#close`, `commit/abort_operation`, `open_file`,
  `UI.scale_factor`, `Pages#selected_page=`; `Sketchup.tempdir` отсутствует
  (используется `Dir.tmpdir`/`ENV[TEMP]`).
- **Ожидается по документации, в живом SU не прогонялись**: SU 2025,
  частичные сценарии SU 2024 (полный прогон не выполнялся).

## Разработка

Dev-цикл — через MCP sketchup-dev: `ext_check` → `ext_install` → `ext_reload` →
`ext_test` (в вызовах `dir=U:/dn1code/sketchup_ext` — родитель репозитория:
раскладка dev_root — `<dir>/<id>/`). Тесты в `dn1sup_benchmark/test/` работают и в
живом SketchUp (`ext_test`), и локально:
`ruby -I dn1sup_benchmark/test/stubs dn1sup_benchmark/test/run_local.rb`
(модельные уходят в skip). Методика набора меняется только с минорной версией
— результаты должны быть сравнимы в рамках одной минорной версии.
