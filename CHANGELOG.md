# Changelog

## 0.3.2 (2026-10-28)

Точечный фикс 0.3.1: после аварийного останова прогона (смена активной
модели) «хвост» `@run_model` не сбрасывался — guard модели срабатывал
вне активного прогона (замечено на юнит-тестах после живых прогонов).

- `guard_model!` действует только в рамках активного прогона (`@state`);
- `Runner.abort_run!` — полный сброс состояния прогона (используется
  секвенсором на ModelChanged); `finish_run` тоже очищает `@run_model`;
- регрессионные тесты: тики вне прогона не зависят от «хвоста» состояния.

## 0.3.1 (2026-10-28)

Исправление «зависания» тяжёлых профилей: шаги large блокировали UI-поток
на минуты (API-01: 125 тыс. контуров ≈ 100 с на повтор + стирание 625 тыс.
сущностей; сетка 500×500 ≈ 100 с), и на время блока была недоступна отмена —
ТЗ §7 требует для больших профилей «безопасные ограничения и возможность
отмены». Измеряемые операции и методика не изменились (тайминг — сумма
длительностей порций работы, простои между тиками не считаются): результаты
0.3.0/0.3.1 сравнимы.

- **Кусковой движок**: задача = фазы, фаза = единицы работы, выполняемые
  порциями ~1 с (размер адаптируется по факту). Между порциями UI-поток
  свободен: работает отмена, меню и панель, панель получает события
  прогресса (сколько единиц из скольких, какая фаза).
- Кусочно теперь выполняются: построение сцен components/grid/textured,
  `API-01` (создание и стирание порциями), `API-03`, `API-06` (цикл =
  порция). Отмена срабатывает максимум через ~1 с.
- Синхронными остались лёгкие тесты (RUBY-01, API-02/04/05, pushpull,
  текстуры, иерархия) и единичные операции вида (zoom_extents — отмечено
  в параметрах теста).
- `benchmark_perform` возвращает `:in_progress` для незавершённого шага
  сцены (внешним оркестраторам: вызывать в цикле до строки-результата).
- Прогресс фаз отражается в панели («Запуск»: N из M, фаза k/n).
- **Проверено в живом SU 2027**: полный small-прогон 32/32 passed; large-прогон
  отзывчив посреди кусков (оценка моста ~1 мс), отмена останавливает за
  секунды, отчёт «cancelled» сохраняется, модель после отмены целая;
  многократно сработал guard смены активной модели — прогон останавливается
  без очистки чужой модели.
- **API-01 в large ограничен 25 тыс. контуров** (было 125 тыс.): цель
  «500 тыс. рёбер» профиля обеспечивает сцена grid (501 тыс. рёбер);
  125 тыс. контуров в одной коллекции деградируют на порядки (замерено
  2026-10-28, SU2027: с ростом модели скорость создания падает ~10×).
- **API-04 исключён из общего балла** (субмиллисекундный — медиана 0.0 мс
  отсекается и делает балл вечным «partial»); сам тест остался.

## 0.3.0 (2026-10-28)

Общий балл в стиле Geekbench (необязательная сводная оценка с опубликованными
весами и базой — ТЗ §3.10, §12). Измерения не менялись: результаты прогонов
0.2.0 остаются сравнимыми с 0.3.0 (тот же набор тестов v2 и версии тестов).

- `Score.compute`: балл теста = base/value (мс) или value/base (fps) к базе;
  категория — геометрическое среднее; общий = 1000 × взвешенное геометрическое
  среднее категорий (веса: API 0.40, графика 0.30, Ruby 0.20, файлы 0.10).
- База — `baseline-small-v1.json`: фактический small-прогон SU 2027.0.264;
  1000 баллов = эта конфигурация. Для профилей без baseline — `unavailable`
  с причиной; пропущенные тесты — `partial` с перечнем.
- Балл в JSON-отчёте (`score`), в HTML-отчёте (секция с формулой), в строке
  сравнения HTML и панели; в панели — в «Обзоре» и «Результатах». Сравнимы
  только баллы одного профиля, иначе помечаются «несравнимо».
- Тесты: база ≈ 1000, машина ×2 ≈ 2000, partial/unavailable, веса = 1.

## 0.2.0 (2026-10-28)

Приведение к ТЗ «SketchUp Benchmark»: новый набор тестов v2, профили по целям
рёбер/инстансов, HTML-панель, JSON-схема, отмена прогона. Результаты прогонов
0.1.0 с новыми прогонами официально несравнимы (другой набор тестов —
сравнение пометит такие пары).

- **Новые тесты**: `RUBY-01` (чистый Ruby), `API-01` рёбра+грани, `API-02`
  группы, `API-03` компоненты (уникальные определения vs повторное
  использование), `API-04` обход со сверкой количества, `API-05` атрибуты
  (запись+обратное чтение), `API-06` транзакции (modify/commit/abort
  раздельно), `DOC-01` сохранение и `DOC-02` открытие контрольной модели
  (фикстура через `ComponentDefinition#save_copy` во временную папку,
  пользовательская модель не сохраняется).
- **FPS**: новые режимы панорамирования и зума (`fps_grid_pan`,
  `fps_grid_zoom`). Автоматический тест переключения страниц УДАЛЁН:
  применение страницы внутри undo-операции фиксирует транзакцию ядра и ломает
  откат (инцидент 2026-10-28, SU2027) — переключение сцен только вручную.
- **Профили**: `small` / `medium` / `large` / `custom` с целями из ТЗ
  (10k/100k/500k рёбер; 100/1k/10k инстансов); формулы вывода параметров сцен
  записываются в отчёт. Профили quick/full удалены.
- **Контракт теста**: у каждой записи — id, версия теста, категория
  (ruby/api/documents/graphics), статус passed/failed/cancelled/skipped,
  параметры, валидация (сверка результатов), диагностика (класс/сообщение/стек).
- **Метрики**: p95 (при ≥10 повторов), ops/с, entities_created,
  file_size_bytes; отсутствующее — `null`, не 0. В meta — schema_version,
  benchmark_version, test_suite_version, параметры среды (DPI, вьюпорт,
  стиль рендера) с указанием источника каждого класса показателей.
- **Отмена**: меню и панель; недозапущенный тест → `cancelled`, отчёт
  сохраняется. Прогон останавливается без очистки, если активная модель
  сменилась посреди прогона.
- **Панель UI::HtmlDialog** (Modus Bootstrap, CSS вендорен — интернет не
  нужен): Обзор / Тесты / Запуск / Результаты / Сравнение / Настройки;
  настройки персистируются (`Sketchup.write_default`). Окно открывается
  только пунктом меню.
- **Сравнение**: проценты только для совместимых пар (одинаковые версия
  теста, единицы, параметры); несовместимые — с указанием причины.
- **Безопасность**: подтверждение перед каждым прогоном с показом нагрузки;
  предупреждение перед heavy-профилями; контроль отката сцен по числу
  сущностей; тесты модели обязаны оставаться на модели прогона.
- **Схема** `dn1sup_benchmark/schemas/result-schema-v1.json` + тест
  соответствия реальных отчётов схеме.
- Проверено: полный small-прогон в живом SU 2027.0.264 (Ruby 3.4.9),
  установка и зелёные тесты в SU 2026.2.243.

## 0.1.0 (2026-10-28)

Первый выпуск.

- Сцены: вложенные группы, лес компонентов, плотная сетка, текстурированные
  боксы (детерминированные генераторы).
- Вьюпорт: FPS-метр (Tool#draw + view.invalidate) в статичном виде и орбите,
  Zoom Extents.
- Иерархия: вход/выход `active_path=`, пошаговый спуск, обход дерева.
- Редактирование: push/pull батча, перемещение инстансов, правка определения.
- Текстуры: генерация PNG чистым Ruby (zlib), загрузка 256/1024/2048,
  батч-наложение, перекраска, цветные материалы.
- Отчёты: JSON + самодостаточный HTML; сравнительный отчёт по прогонам.
- Меню Extensions → DN1Sup → Benchmark; прогон из меню не блокирует UI.
